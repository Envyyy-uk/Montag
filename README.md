# Автомонтаж (auto-editor)

Особиста програма, яка з кількох сирих відео робить майже готовий монтаж: кліп під музику і 3 вертикальні ролики.
Працює локально на ноутбуці (Windows 11, NVIDIA RTX). Платний лише AI-аналіз кадрів (Gemini Flash) у межах місячного ліміту.

## Встановлення (Windows)

1. Python 3.12+, драйвер NVIDIA, FFmpeg з NVENC у `PATH` (наприклад, збірка gyan.dev «full»).
2. У папці репозиторію:
   ```powershell
   py -3.12 -m venv .venv
   .venv\Scripts\activate
   pip install -e ".[dev]"
   copy .env.example .env    # і заповни ключі
   ```
3. Перевірка системи і створення бази:
   ```powershell
   python -m core check
   python -m core init
   ```
4. Сервер (разом із воркером): `python -m server.app` → інтерфейс http://127.0.0.1:8765/ , API http://127.0.0.1:8765/docs
5. Тести: `pytest`

## Введення відео

- **Прямий upload з докачуванням** — протокол tus 1.0 на `/api/uploads`
  (метадані `filename` і `project_id`). Обрив зв'язку не страшний: клієнт продовжує з місця зупинки.
- **Локальний inbox** — поклади файли з карти в `inbox/<назва проєкту>/` (можна з підпапками `DCIM/...`).
  Файл забирається, коли закінчилось копіювання; нова папка створює новий проєкт.
  Службові файли камер (`.LRV`, `.THM`) ігноруються.
- Після прийому: оригінал у `library/<проєкт>/originals/` (лише читання), ffprobe,
  проксі `proxies/<id>_1080.mp4` (монтаж) і `<id>_480.mp4` (Gemini), HDR iPhone → SDR Rec.709.
- «Монтувати»: `POST /api/projects/<id>/edit`, або автоматично через 10 хв без нових файлів.
- Статус черги: `GET /api/queue`.

## Аналіз (локально, безкоштовно)

Після проксі кожне відео проходить етап `analyze_media` (по 480p-проксі):
- **сцени** — PySceneDetect (AdaptiveDetector); сцени довші за 6 с ріжуться на шматки 2–4 с;
- **фільтр браку** — різкість, яскравість, контраст, рух, тряска; причини: кишеня, темрява,
  пересвіт, однотонне, розмито, тряска, закороткий. Пороги — у `styles/filters.json`
  (`standard` і м'якший `lofi`; за замовчуванням `DEFAULT_FILTER_PRESET=lofi`);
- **звук** — гучність у часі і сплески натовпу (≥ 0,5 с, на 6 дБ голосніше фону);
- **мова** — faster-whisper (`WHISPER_MODEL`, на CUDA, якщо є), транскрипт і `.srt`.
  Перший запуск завантажує модель з інтернету.

Результати: `library/<проєкт>/analysis/` і `GET /api/media/<id>/analysis`.

## Структура

```
core/      конфіг, SQLite, перевірка системи
server/    FastAPI, API, авторизація, завантаження
worker/    черга, оркестрація етапів
analysis/  сцени, фільтр, звук, whisper, gemini, кадрування
edit/      вибір кадрів, ритм, вставки, переходи, вертикаль
render/    ffmpeg-фільтри, стилі, NVENC, експорт FCPXML
sources/   прямий upload, Google Drive, локальний inbox
styles/    JSON-пресети стилів і переходів
web/       React PWA, Liquid Glass UI
tests/     юніт-тести
library/   дані користувача (не в git)
```

## Безпека

- Секрети лише в `.env` (не в git).
- Сервер слухає тільки на `127.0.0.1` або Tailscale-адресі; `0.0.0.0` заборонено конфігом.
- Оригінали відео ніколи не змінюються і не видаляються.

## AI-оцінка (Gemini Flash)

- Ключ: `GEMINI_API_KEY` у `.env` (білінговий акаунт з кредитами Google AI Pro). Перевірка: `python -m core gemini-ping`.
- «Монтувати» → `score_project`: шматки, що пройшли локальний фільтр, групуються у вікна відео
  (≤ `GEMINI_WINDOW_SECONDS`) і йдуть одним **Batch**-завданням (−50% вартості). Відповідь — JSON за схемою
  (оцінка 0–10, опис, теги, придатність для вертикалі, тип події); невалідна — одна повторна спроба, далі локальні метрики.
- **Кеш**: оцінка прив'язана до шматка і версії смаку/стилю — повторний монтаж нічого не надсилає.
- **Бюджет**: місячний ліміт `MONTHLY_BUDGET_USD`, вартість кожного запиту за токенами з відповіді,
  резерв під ще не оплачені batch-і, денний ліміт запитів. Прогноз понад `CONFIRM_THRESHOLD_USD` чекає
  підтвердження (`GET /api/confirmations`, `POST /api/jobs/<id>/confirm`). Після ліміту — лише локальні метрики.
- Ціни — у `core/pricing.json`; невідома модель рахується за консервативним `_default`.
- Смак: `taste.md` + картинки-приклади в `library/taste/take/` і `library/taste/skip/` (до 20 у кожній).
- Стан бюджету й історія: `GET /api/budget`.

## Режим 1: кліп під музику

Додай у проєкт трек (mp3/wav/m4a) разом із відео — він аналізується окремо (`analyze_track`):
темп, біти (уточнені до удару, похибка < 1 кадру), сильні долі, енергія, дропи і приспіви.

Після AI-оцінки етап `edit_project` збирає кліп:
- найенергійніший шматок треку заданої довжини (60 с), межі — на початку такту;
- склейки на біт: низька енергія — раз на такт, середня — раз на 2 біти, дроп/приспів — кожен біт;
  кадр-«герой» (9–10, верхні 10% матеріалу) може тримати до 2 тактів;
- вибір кадрів: оцінка + різноманітність (сцена, відео, теги, камери) + хронологія + енергія;
- живі вставки зі сплесків натовпу: 1–3 с, пауза ≥ 8 с, ≤ 4 на хвилину, не на самому дропі;
  трек приглушується на −12 дБ з атакою і відпуском 150 мс;
- результат: `library/<проєкт>/edits/clip_vNNN/` — `timeline.json`, `mix.wav`;
  готовий кліп — `library/<проєкт>/exports/<проєкт>_clip_vNNN.mp4` (1080p) і `_720p.mp4` для телефона.

API: `GET /api/projects/<id>/edits`, `GET /api/edits/<id>/preview`, `GET /api/edits/<id>/timeline`,
`GET|PUT /api/projects/<id>/clip-settings` (довжина, межі треку, вставки, ритм, ваги тегів),
`POST /api/projects/<id>/reedit` — перемонтаж на кешованих оцінках, без запитів у Gemini.

## Стилі й переходи

Стилі — JSON у `styles/`: «вигляд» (`look`), три рівні інтенсивності (`levels`), пороги фільтра браку,
дозволені переходи. Стартові: **MiniDV-концерт**, **Літня поїздка**, **VHS 90-х**, **Чистий**.

- MiniDV: 480 рядків з електронною різкістю, кольоровий шум і зерно, знижена насиченість,
  холодно-ціанові тіні, лінії розгортки, віньєтка, жовта дата й час зйомки (секунди тікають).
- Затвердження рівня: `POST /api/styles/<id>/test` (за бажанням `{"media_id": …, "start": …}`) робить
  три 5-секундні рендери → `GET /api/styles/<id>/test/1|2|3` → `POST /api/styles/<id>/approve {"level": 2}`.
- Стиль проєкту: `PUT /api/projects/<id>/style`; без нього — `DEFAULT_STYLE`.

Переходи (`render/transitions.py`, тривалість у бітах): біла спалах-склейка, пробій зумом, розмита панорама,
VHS-збій, перемотка плівки, стоп-кадр, засвітка плівки. Ефектні — лише на акцентах (дроп, приспів,
живі вставки), не більше `max_share` склейок; решта різкі. Вимкнути для проєкту:
`PUT /api/projects/<id>/clip-settings {"transitions": false}` або `{"disabled_transitions": ["glitch"]}`.
Готовий mp4: `GET /api/edits/<id>/video`. Висота рендеру — `RENDER_HEIGHT`.

## Проєкт DaVinci Resolve

Після готового mp4 окремим завданням збирається папка
`library/<проєкт>/exports/<проєкт>_clip_vNNN_davinci/`:

- `<…>.fcpxml` — FCPXML 1.9 з **відносними** шляхами (папку можна переносити на інший диск);
- `<…>_абсолютні.fcpxml` — те саме з повними шляхами, якщо Resolve не прийме відносні;
- `media/originals/` — оригінали (жорсткі посилання на `library/…/originals`, місця не займають),
  `media/styled/` — стилізовані кліпи з запасом до 1 с з кожного боку, `media/audio/` — трек.

Доріжки: **V1** — оригінали без стилю (вимкнена), **V2** — зі стилем (увімкнена), **A1** — трек з автоматизацією
приглушення, **A2** — живі вставки з тією ж гучністю, що в mp4. Маркери: дроп, приспів, вставки (на кліпах V1).
Таймкод джерел (iPhone пише час доби) враховано. Імпорт у Resolve: *File → Import → Timeline…* → вибрати `.fcpxml`.

API: `GET /api/edits/<id>/davinci` (стан і шлях), `POST /api/edits/<id>/davinci` (зібрати заново).

## Режим 2: вертикальні ролики

Після AI-оцінки етап `vertical_project` робить 3 ролики 9:16 (1080×1920, 30 fps, H.264, зі стилем):
- кожен — навколо одного сильного моменту (оцінка + сплеск натовпу + придатність для вертикалі):
  розгін (безперервна зйомка перед піком або раніші сильні шматки), пік, 1,5 с після піку;
  ролики не перетинаються за матеріалом і беруться з різних частин події;
- кадрування: MediaPipe шукає обличчя і людей, вікно плавно стежить за головним об'єктом;
  якщо вікно обріже важливе — весь кадр із розмитою копією зверху і знизу; вертикальні оригінали не кадруються.
  Моделі (~5 МБ) завантажуються в `library/models/` при першому запуску;
- звук: `live` (живий, за замовчуванням), `track` (шматок треку) або `none` (без музики — щоб додати
  бібліотечну в TikTok/Instagram).

Файли: `exports/<проєкт>_vertical_vNNN_<1..3>.mp4`. API: `GET|PUT /api/projects/<id>/vertical-settings`
(`count`, `length` 15–25, `audio`), `POST /api/projects/<id>/verticals`, `GET /api/edits/<id>/reels/<n>`.

## Правки словами, смак і автовибір стилю

**Правка:** `POST /api/projects/<id>/requests {"text": "більше натовпу"}` → відповідь із підсумком змін
і питанням «Тільки тут чи назавжди?» → `POST /api/requests/<id>/apply {"scope": "here" | "always"}`.
- Часті фрази розбираються локально, без Gemini: «більше/менше <чого>», «швидше/спокійніше», «без вставок»,
  «45 секунд», «з 1:20 до 2:10», «без переходів», «в стилі VHS», «більше зерна», «вертикалі без музики».
  Решта — один миттєвий запит у Gemini (JSON-схема, облік вартості, бюджет).
- «Тут» — налаштування проєкту і перемонтаж на кешованих оцінках (без нових запитів на аналіз).
- «Назавжди» — правило для всіх проєктів: таблиця правил і розділ у `taste.md`
  (блок правил не скидає кеш оцінок). Розділ «Смак»: `GET|PUT /api/taste`, `PUT|DELETE /api/taste/rules/<id>`,
  приклади «беру / не беру»: `POST /api/taste/examples/take|skip` (картинка).
- Тег «натовп» береться і зі сплесків звуку, тож «більше натовпу» працює навіть без оцінок Gemini.

**Автовибір стилю:** за типом події, який Gemini визначає під час оцінки. Впевнено — стиль ставиться сам;
змішаний матеріал або низька впевненість — пропозиція з поясненням у `settings.style_auto`
(`POST /api/projects/<id>/style-suggestion {"accept": true}` або `{"style_id": "vhs-90s"}`).
Пріоритет: стиль, обраний користувачем → правило «назавжди» → автовибір → `DEFAULT_STYLE`.

**Стилі словами:** `POST /api/styles/generate {"text": "теплий вицвілий з зерном"}` → чернетка з
3 рівнями + тестовий 5-секундний рендер → `POST /api/styles/drafts/<id>/save`. Без Gemini працює
генератор за ключовими словами. Стилі користувача — у `library/styles/`.

## Google Drive (відео поза домом)

**Налаштування (один раз, на ноутбуці):**
1. [console.cloud.google.com](https://console.cloud.google.com) → той самий проєкт, що й для Gemini →
   *APIs & Services → Library* → увімкни **Google Drive API**.
2. *OAuth consent screen*: тип **External**, додай себе в тестові користувачі, потім **Publish app**
   (статус *In production*; без цього токен перестає працювати через 7 днів). Перевірка Google для
   особистого застосунку не потрібна — під час входу просто буде попередження «неперевірений застосунок».
3. *Credentials → Create credentials → OAuth client ID → Desktop app* → завантаж JSON у папку репозиторію
   як `client_secret.json` (він у `.gitignore`).
4. У `.env`: `GOOGLE_CLIENT_SECRET_FILE=client_secret.json`, `GOOGLE_TOKEN_FILE=library/google_token.json`.
5. `python -m sources.gdrive auth` — відкриється браузер, дозволь доступ. Токен збережеться в `library/`.

**Як працює:**
- Новий проєкт у програмі створює в Drive `Автомонтаж/<назва>/` і `Готово/`. Папка, створена в Drive
  з телефона, створює проєкт у програмі.
- Воркер раз на `DRIVE_POLL_SECONDS` дивиться в папки проєктів. Файл забирається, коли двічі поспіль має той
  самий розмір і MD5 (завантаження з телефона завершилось), перевіряється розмір і MD5, потрапляє в бібліотеку
  і лише тоді видаляється з Drive. Пошкоджене завантаження — повтор, у Drive файл лишається.
- Готові mp4 (720p-превʼю кліпу і вертикалі) дублюються в `Готово/` — їх можна дивитися, коли ноутбук вимкнений.
- Стан: `GET /api/drive`.

## Веб-інтерфейс (PWA)

Мобільний інтерфейс у стилі Liquid Glass з деталями камкордера (лише темна тема): розмиті вогні сцени,
лінії розгортки, скляні панелі з відблиском від нахилу телефона, червона крапка REC, жовтий таймкод,
VHS-екран «PLAY ▶» під час обробки. Шрифти: Space Grotesk (кирилиця — Manrope), JetBrains Mono.

Екрани: **Черга** (статуси, прогрес, $ / ліміт) · **Проєкт** (превʼю, смужка енергії треку з перетягуваними
межами, перемикачі переходів, кліп і вертикалі, правка словами «тільки тут / назавжди», mp4 і DaVinci,
пропозиція стилю, підтвердження вартості) · **Додати відео** (новий проєкт, вибір файлів, завантаження з
докачуванням) · **Вертикальні** («Поділитися» через меню iOS, вибір звуку) · **Стилі** (тестові рендери,
затвердження рівня, стиль словами) · **Смак** (інструкція, приклади, правила) · **Ліміт** (ліміт, поріг,
історія, сповіщення).

- Готова збірка лежить у `web/dist` і роздається сервером — Node на ноутбуці не потрібен.
- Розробка інтерфейсу: `cd web && npm install && npm run dev` (проксі на сервер :8765), збірка — `npm run build`.
- Додати на iPhone: Safari → «Поділитися» → «На головний екран». Web Push працює для такої PWA (iOS 16.4+)
  і лише через HTTPS — це Спринт 12 (Tailscale + `tailscale cert`). Увімкнути — екран «Ліміт» → «Сповіщення».

## Доступ з iPhone: Tailscale, HTTPS, PIN

1. Встанови Tailscale на ноутбук і iPhone, увійди в один акаунт.
2. В адмінці Tailscale (DNS) увімкни **MagicDNS** і **HTTPS Certificates**.
3. На ноутбуці: `python -m core tailscale-cert` — сертифікат ляже в `library/tls/` (термін 90 днів; повтори команду, коли закінчиться).
4. У `.env` задай `ACCESS_PIN=` (щонайменше 4 цифри). Без PIN віддалений доступ закритий повністю.
5. Запусти сервер (`python -m server.app`): він слухає `http://127.0.0.1:8765` для ноутбука і `https://<tailscale-IP>:8443` для телефону. На 0.0.0.0 не слухає ніколи.
6. На iPhone відкрий у Safari `https://<машина>.<tailnet>.ts.net:8443`, введи PIN (сесія діє 90 днів), потім «Поділитися → На початковий екран».

Після 5 хибних PIN адресу блокує на 5 хв, далі блокування подовжується. Запити із самого ноутбука PIN не потребують.

**Куди вантажити відео** вирішує екран «Додати». Напряму на ноутбук програма вантажить, коли iPhone з'єднаний з ним напряму через домашню мережу і швидкість не нижча за `UPLOAD_DIRECT_MIN_MBPS` (20 Мбіт/с). В усіх інших випадках екран пропонує папку проєкту в Google Drive. Коли ноутбук недоступний, з'являється банер із збереженими посиланнями на папки Drive.

**Сон Windows.** Поки в черзі є завдання, ноутбук не засинає (екран гасне як звичайно). Коли черга порожня, звичайна поведінка повертається.

**Автозапуск у Windows** (від свого користувача, при вході):

```bat
schtasks /Create /TN "Автомонтаж" /SC ONLOGON /RL LIMITED ^
  /TR "\"C:\Montag\.venv\Scripts\pythonw.exe\" -m server.app" /F
```

(Робоча тека в «Планувальнику завдань» → «Дії» → «Почати в»: `C:\Montag`.)

## Керування через Claude (MCP)

Програмою можна керувати з Claude Desktop на цьому ж ноутбуці: «що в черзі?», «покажи кліп Brixton»,
«зроби швидше на приспіві», «три вертикалі по 20 секунд з живим звуком».

1. Програма має бути запущена (`python -m server.app`).
2. У Claude Desktop: Settings → Developer → Edit Config, додай у `claude_desktop_config.json`:

```json
{
  "mcpServers": {
```

### Claude з iPhone (MCP через Tailscale Funnel)

Claude на iPhone працює з хмари Anthropic, а не з телефона, тому до ноутбука йому потрібна публічна адреса.
Її дає Tailscale Funnel. В інтернет виводиться **лише MCP**: застосунок, API і відео лишаються доступні тільки в tailnet.

1. У `.env`: `MCP_REMOTE=true` і `ACCESS_PIN` щонайменше з 6 цифр (MCP відкритий в інтернет, 4 цифри замало).
2. В адмінці Tailscale дозволь Funnel для ноутбука (Access controls → `funnel` attribute).
3. Перезапусти програму, потім `python -m core tailscale-funnel on`. Команда покаже адресу `https://<машина>.<tailnet>.ts.net/mcp`.
4. У Claude (claude.ai або застосунок): Settings → Connectors → Add custom connector → встав адресу.
   Відкриється сторінка ноутбука: введи PIN і натисни «Дозволити».
5. Готово: у чаті на iPhone можна писати «що з монтажем Brixton?» або «покажи вертикалі».

Безпека: після 5 хибних PIN сторінку блокує на 5 хв для всіх, далі вдвічі довше щоразу.
Токени в базі зберігаються лише хешами, доступ діє 24 год і оновлюється сам.
Підключення видно на екрані «Ліміт», кнопка «Відкликати» вимикає доступ одразу.
Вимкнути Funnel повністю: `python -m core tailscale-funnel off`.
